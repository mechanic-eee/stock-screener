## 인과 사슬 (왜 하나가 넷이 됐나)

1. **신선도 가드가 달력만 봤다.** `_biz_days_behind(last, today_utc)`는 휴장을 모른다. 9/4 → 9/8은 달력상 2영업일이지만 실제로는 **직전 거래일**이다. 가드는 "낡은 캐시를 좋은 스냅샷 위에 덮지 마라"는 옳은 규칙이었으나, 기준이 틀렸다.
2. **스냅샷이 멈추자 로컬이 라이브로 폴백했다.** `review._rank_map` → `recommend._load_rows`는 사이드카에 없는 종목마다 `get_fundamentals`를 부르고, 9/6에 캐시가 비워진 상태라 **종목당 DART 최대 13콜**. 실측 `_load_rows` 303초, review 전체 4시간.
3. **시간 제한이 프로세스 트리를 못 죽였다.** Task Scheduler는 부모만 종료한다. python 자식은 살아남아 감시·알림을 계속 수행했다.
4. **하트비트가 늦으니 워치독이 이틀 연속 울었다.** 워치독 판정 자체는 정직했다(그 시각에 실제로 하트비트가 없었다).

## 교훈

- **"휴일"은 모든 신선도 가드의 사각지대다.** 달력 대신 *같은 피드의 기준 시계열*(벤치마크)을 쓰면 휴장·조기폐장이 자동으로 상쇄된다. 시세 축에 이미 있던 이 원리(P0-2 `_market_last_date`)를 스캔 축에는 안 썼던 것이 사고의 시작.
- **캐시를 비우는 변경(스키마 컷오프 상향)은 그 자체로 이벤트다.** 다음에 대량 무효화를 할 때는 (a) 재구축을 언제 어디서 치르는지 명시하고 (b) 감시 경로가 라이브 폴백으로 빠지지 않는지 먼저 확인한다.
- **감시 스크립트는 데이터를 만들지 않는다.** 랭킹이 없으면 랭킹 없이 도는 게 맞다(하트비트가 우선). 감시 경로에 네트워크 폴백을 열어 둔 것이 4시간의 직접 원인.
- **부모만 죽이는 종료는 종료가 아니다.** 스케줄러의 시간 제한을 신뢰하지 말고, 시작 시 청소하는 쪽이 단순하고 확실하다.
- **복잡한 안전장치보다 빠른 실행이 낫다.** 타임아웃 러너 3종 실패 후, 병목을 없애자 러너가 필요 없어졌다.
