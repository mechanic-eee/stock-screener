# 서비스 정의서 — 개인 보유 규율 대시보드 (review.py)

> 작성 2026-07-22 · 대상 서비스: `scripts/review.py` (개인 보유종목 규율 대시보드)
> 상태: **완성 — 멀티에이전트 감사(31에이전트/24건 확정) 반영, CI green, 매일 08:10 자동 운영**
> 위치: 폭락주 스크리너 시스템의 **⑥번째 단계(감시의 확장)** — 개인 계좌 전체를 매일 규칙으로 점검

---

## 1. 한 줄 정의
**"매일 아침, 내가 실제로 들고 있는 모든 종목을 *내가 미리 정한 규칙*에 비춰 자동 점검하고, 조치가 필요한 것만 텔레그램으로 알려주는 대시보드."**

---

## 2. 배경 — 왜 만들었나 (해결하는 문제)
2026-07 개인 계좌 점검에서 드러난 3가지 구조적 갭:

1. **출구 규칙의 부재.** 보유 7종목 중 6종목에 손절선이 없었다. "들어가는 문(매수)"만 있고 "나가는 문"이 무방비 — 논거가 깨져도 알아챌 장치가 없었다.
2. **처분효과(disposition effect).** 이익 난 종목(PYPG +50%)은 즉시 팔면서, 손실 난 종목(레버리지 3종·파두 −48%)은 손을 못 대는 편향. 아픈 결정을 미루다 손실이 굳는다.
3. **감춰진 집중 리스크.** 파두 + 샌디스크가 별개 종목처럼 보였지만 실은 같은 낸드 사이클 베팅 — 계좌의 47~51%가 한 테마에 몰려 있었다.

이 갭들은 **매일 사람이 손으로 점검하면** 메울 수 있지만, 실제로는 잊힌다. 그래서 **기계가 매일 대신 점검**하게 한다.

---

## 3. 목적
- 보유 종목의 **규율 위반을 매일 자동으로 표면화** — 손절선 미설정, 손절 근접/이탈, 위험공시, 깊은 손실, 테마 과집중.
- **"오늘 조치가 필요한가?"에 매일 답**을 주되, 사람이 최종 결정하도록 정보만 제공.
- 잊기 쉬운 **계획된 행동(2차 트랜치 등)의 도래를 알림.**

---

## 4. 핵심 설계 원칙 (가장 중요)
### ★ 타이밍 신호를 만들지 않는다 — "규칙 판정"만 한다
"매일 사라/팔라"를 예측하는 매매 신호는 **이 시스템의 백테스트에서 기각**됐다(off_lows IC −0.123, t −5.5 — "바닥 확인 대기"는 계량적 손해). 매일 매수/매도 신호를 생성하면 그것은 **데일리 반응매매·처분효과를 자동화**하는 것 — 이 서비스가 막으려는 바로 그 병을 악화시킨다.

그래서 대시보드는 **미래를 예측하지 않는다.** 오직 **"내가 이미 정해둔 규칙이 오늘 걸렸는지"**만 판정한다. 판단의 주체는 언제나 사람이고, 도구는 규율의 눈을 대신할 뿐이다.

### ★ '줏기(추가매수)'는 미리 계획한 것만, 그리고 붕괴 중엔 억제
"더 살 것" 축은 매일 딥을 추격하지 않는다. **미리 기록해 둔 계획(예: NVO 2차 트랜치 8/10)만** 도래 시 알린다. 나아가 그 종목에 **청산검토(🔴) 플래그가 떠 있으면 추가 알림을 억제**한다 — 무너지는 포지션에 물타기하는 것을 구조적으로 막는다.

## 5. 기능

### 5.1 종목별 규율 판정
각 보유 종목을 매일 아래 규칙으로 판정해 태그를 부여한다:

| 태그 | 의미 | 발동 규칙 |
|---|---|---|
| 🔴 **청산검토** | 논거 훼손 — 나가는 문 | 손절 이탈 / 위험공시(DART 자본잠식·감사비적정·부도) / EDGAR 🔴 희석·상폐 공시(424B·S-1·25·NT10) |
| 🟠 **축소·재평가** | 주의 — 재점검 필요 | **손절선 미설정** / 손절 근접(여유 ≤8%) / EDGAR 🟠(8-K) / 스크리너 랭킹 하위 50% 강등 / 깊은 손실(≤−35%) |
| 🔵 **추가예정** | 미리 계획한 추가 도래 | planned_add 날짜 창(−3~+7일). 단 🔴 있으면 억제(물타기 방지) |
| 🟢 **유지** | 규칙 이상 없음 | 위 어느 것도 걸리지 않음 |
| ⚪ **정보없음** | 판정 불가 | 가격조회 실패(거래정지·상폐·데이터장애) / 데이터 오류 |

### 5.2 테마 집중도 경보
보유를 테마별로 합산(원화는 USD 환산)해 비중을 계산하고, 미리 정한 편안한 한도(comfort_max_pct)를 넘으면 ⚠️ 초과 표시. (예: 낸드 한도 40% → 현재 51% ⚠️)

### 5.3 일일 하트비트 (생존 신호)
`monitor.py`가 하트비트를 review에 양보하므로, review가 **유일한 일일 맥박**이다. "알림 없음"과 "감시가 죽음"을 구분하기 위해 — 조치할 게 없어도 "🟢 이상 없음"을, holdings 파일이 없거나 손상돼도 "⚪ 스킵" 신호를 반드시 한 번은 보낸다.

### 5.4 시스템 포지션과의 알림 분리
스크리너 시스템이 발굴한 포지션(`system:true`, 예: NVO)의 알림은 `monitor.py`가 소유한다. review는 콘솔 대시보드엔 표시하되 **텔레그램 알림에선 제외** — 같은 사건의 이중 전송을 막는다.

## 7. 전체 투자 루프에서의 위치
```
① 발굴        ② 선별        ③ 결정+사이징   ④ 추적        ⑤ 감시(시스템)   ⑥ 규율 대시보드(개인 전체)
앱·알림   →  워치리스트  →  decide.py  →  track.py  →  monitor.py   →  review.py ★
(점수상위)   (관심종목)     (DECISIONS)    (수익률)      (시스템 포지션)    (실제 계좌 전체를 매일 규칙 점검)
```
⑤ monitor는 **시스템이 발굴한 포지션**을 본다. ⑥ review는 **실제 브로커 계좌 전체**(시스템 밖 개인 매매 포함)를 본다 — 시스템의 관할 밖에 있던 개인 보유를 같은 규율 아래로 들여온다.

## 8. 기대효과
- **출구 규율의 상시화:** 손절선 없는 포지션이 매일 🟠로 뜨므로, "출구 없이 들고 있는 상태"가 방치되지 않는다.
- **처분효과 억제:** 손실 종목의 재평가 신호를 감정과 무관하게 매일 들이민다 — 아픈 결정을 미루기 어렵게 만든다.
- **집중 리스크 가시화:** 테마 과집중을 숫자로 매일 표면화 → "분산인 줄 알았던 집중"을 조기 인지.
- **놓친 계획 방지:** 2차 트랜치 등 미리 정한 행동의 도래를 자동 리마인드.
- **물타기 방지:** 붕괴 중 포지션엔 추가 알림을 억제해, 구조적으로 나쁜 추가매수를 막는다.
- **관측 가능성:** 매일 하트비트로 "조용한 날"과 "감시가 죽은 날"을 구분.

## 11. 요약
개인 투자자가 가장 흔히 실패하는 지점 — **출구 규율의 부재, 처분효과, 숨은 집중** — 을 매일 아침 기계가 대신 점검한다. 미래를 예측하지 않고(타이밍 신호 금지), 사용자가 스스로 정한 규칙이 걸렸는지만 판정해 조치가 필요한 것만 알린다. 판단의 주체는 사람, 규율의 눈은 도구가 맡는다.

## 12. 사용법 (매일 / 매매 시 / 설정)

### 12.1 매일 아침 (30초) — 텔레그램만 보면 된다
평일 08:10에 "📋 보유 규율 점검" 한 통이 온다. 손 댈 것 없이 **읽기만** 하면 된다:
- **"🟢 개인 보유 규칙 이상 없음 · 조치 불필요"만 왔다** → 끝. 오늘 할 일 없음. (이 한 통이 하트비트 = 감시가 살아있다는 신호이기도 하다.)
- **종목이 나열돼 왔다** → 각 줄의 태그(🔴/🟠/🔵)를 보고 아래 12.2 대응표대로.
- **아무것도 안 왔다** → 감시가 죽은 것 → §6 고장 대응(대시보드 문서 아님, 사용-매뉴얼 §6).

> 콘솔로 직접 보고 싶으면: `.venv\Scripts\python.exe scripts\review.py` (텔레그램 없이 전체 표 출력).

### 12.2 태그 → 대응 행동
| 태그 | 뜻 | 당신의 행동 |
|---|---|---|
| 🔴 **청산검토** | 손절 이탈·위험공시·희석공시 | **당일 청산이 기본.** 원인 확인 후 실제 매도 → holdings.json에서 그 종목 제거(12.3) |
| 🟠 **손절선 미설정** | 출구 규칙 없음 | 손절 가격을 정해 holdings.json의 `stop`에 기입(12.3) — 이 종목이 매일 뜨는 건 "아직 안 정했다"는 뜻 |
| 🟠 **손절근접** | 손절까지 ≤8% | 손절 유지할지/조정할지 결정. 대개는 그대로 두고 관찰 |
| 🟠 **랭킹 강등·깊은손실** | 논거 약화 | thesis 재점검 — 계속 들고 갈 근거가 남았나 |
| 🔵 **계획된 추가** | 미리 정한 추가 도래 | 그날 조건(실적 확인 등) 충족 시 추가매수 집행 → 체결 후 holdings.json 수량·평단 갱신 |
| ⚠️ **테마 초과** | 한 테마가 한도 초과 | 그 테마 비중 축소 검토(집중 리스크) |
| ⚪ **정보없음** | 가격조회 실패·데이터 오류 | 거래정지·상폐 여부 확인, 또는 holdings.json 형식 점검 |

> **핵심:** 대시보드는 *알려줄 뿐* 팔거나 사주지 않는다. 실제 매매는 증권사 앱에서 직접, 그 뒤 holdings.json을 맞춰준다.

### 12.3 매매·손절 변경 시 — holdings.json 갱신 (필수)
대시보드의 정확도는 `data/holdings.json`이 실계좌와 일치하는지에 달렸다. **매수/매도/손절 변경 때마다 갱신**한다.

**방법 A — Claude에게 위임(권장):** 한 줄로 시키면 된다.
- "파두 손절 5만원으로 잡아줘" → stop 갱신
- "GDXU 7주 다 팔았어" → 해당 종목 제거
- "NVO 20주 더 샀어, 평단 52" → 수량·평단 갱신(가중평단 반영)
- "테슬라 10주 250달러에 새로 샀어" → 새 종목 추가

**방법 B — 직접 편집:** `data/holdings.json`의 해당 항목에서 `shares`·`cost`·`stop`을 수정. 필드 의미:
- `stop`: 손절가(종가 기준). **없으면 `null`** → 대시보드가 "손절선 미설정" 🟠으로 매일 상기.
- `theme`: 테마 태그(집중도 계산용). `system`: 스크리너가 발굴한 픽이면 `true`(텔레그램은 monitor가 담당).
- `planned_add`: `{"date":"2026-08-10","note":"2차 트랜치"}` — 미리 정한 추가.
- (편집 후 JSON 형식 유의 — 마지막 항목 뒤 콤마 금지. 깨져도 대시보드는 "⚠️ 파싱 오류" 하트비트를 보내 알려준다.)

### 12.4 Claude에게 시키는 흔한 한 줄
| 한 줄 요청 | Claude가 하는 것 |
|---|---|
| "보유 점검해줘" | review 실행 → 태그·테마집중·대응 권고 보고 |
| "X 손절 N원으로" / "X 팔았어" / "Y 샀어" | holdings.json 갱신 |
| "낸드 비중 얼마야?" | 테마 집중도 계산 보고 |
| "X 추가 계획 8/10 걸어줘" | planned_add 설정 |
| "테마 한도 바꿔줘(낸드 30%)" | themes.comfort_max_pct 조정 |

### 12.5 설정 조정 (선택)
- **손실 재평가 문턱**(기본 −35%): `review.py --loss-alert 25`
- **손절 근접 경고**(기본 8%): `review.py --stop-near 5`
- **테마 한도**: holdings.json의 `themes.<이름>.comfort_max_pct`
